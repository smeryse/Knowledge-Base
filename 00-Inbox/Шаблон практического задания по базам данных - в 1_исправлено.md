## 1. Инфологическая модель (ER-диаграмма Чена)

**Сущности:**
- Лаборатория (id, название, корпус, телефон)
- Сотрудник (id, ФИО, email, телефон, дата_рождения)
- Должность (id, название, оклад)
- Научный_проект (id, название, бюджет, дата_начала, дата_окончания)
- Грант (id, название, сумма, источник, дата_получения)
- Публикация (id, название, дата, тип)
- Оборудование (id, название, инвентарный_номер, стоимость, дата_покупки)
- Заявка_на_оборудование (id, дата, статус, обоснование)

**Связи (кардинальность, обязательность):**
- Лаборатория (1, обязательна) — работает_в — Сотрудник (M, обязателен)
  Каждый сотрудник обязательно приписан ровно к одной лаборатории; лаборатория может иметь много сотрудников.
- Лаборатория (1, обязательна) — ведётся_в — Научный_проект (M, необязателен)
  Лаборатория может вести много проектов; проект принадлежит ровно одной лаборатории.
- Лаборатория (1, обязательна) — закреплено_за — Оборудование (M, необязательно)
  Оборудование закреплено за одной лабораторией; лаборатория может иметь много оборудования.
- Должность (1, обязательна) — занимает — Сотрудник (M, необязателен)
  Сотрудник занимает ровно одну должность; должность может быть у многих сотрудников или вакантна.
- Сотрудник (M, необязателен) — участвует_в — Научный_проект (M, необязателен)
  Связь M:N с атрибутами "роль" и "дата начала участия".
- Сотрудник (M, необязателен) — является_автором — Публикация (M, необязателен)
  Связь M:N с атрибутом "порядок автора".
- Грант (1, необязателен) — финансирует — Научный_проект (M, необязателен)
  Грант может финансировать несколько проектов; проект может не иметь гранта.
- Сотрудник (1, обязателен) — подал — Заявка_на_оборудование (M, необязательна)
  Один сотрудник может подать много заявок; каждая заявка от одного сотрудника.
- Оборудование (1, обязательно) — включено_в — Заявка_на_оборудование (M, необязательна)
  Один прибор может фигурировать в нескольких заявках; заявка на один прибор.

## 2. Физическая модель реляционной БД. Нормализация до 3НФ

Физическая модель:

```
Laboratory(laboratory_id PK, name, location, foundation_year)
Position(position_id PK, title, salary)
Employee(employee_id PK, last_name, first_name, email UK, phone, birth_date,
         hire_date, laboratory_id FK, position_id FK)
Grant(grant_id PK, name, amount, source, received_date)
ScientificProject(project_id PK, name, budget, start_date, end_date, grant_id FK)
Publication(publication_id PK, name, publication_date, type)
Equipment(equipment_id PK, name, inventory_number UK, cost, purchase_date, laboratory_id FK)
EquipmentRequest(request_id PK, request_date, status, justification, employee_id FK, equipment_id FK)
EmployeeProject(employee_id PK FK, project_id PK FK, role, participation_start)
PublicationAuthor(publication_id PK FK, employee_id PK FK, author_order)
```

### Функциональные зависимости (ФЗ)

| Таблица | Функциональные зависимости | Обоснование 3НФ |
|---|---|---|
| Laboratory | laboratory_id → name, location, foundation_year | PK простой, нет частичных/транзитивных |
| Position | position_id → title, salary | PK простой, 3НФ |
| Employee | employee_id → last_name, first_name, email, phone, birth_date, hire_date, laboratory_id, position_id | PK простой. Нет ФЗ laboratory_id → name (лаборатория) — такой атрибут не входит в таблицу. Нет ФЗ position_id → salary — оклад в Position. **3НФ** |
| Grant | grant_id → name, amount, source, received_date | 3НФ |
| ScientificProject | project_id → name, budget, start_date, end_date, grant_id | PK простой. grant_id → (данные гранта) не входят в таблицу. **3НФ** |
| Publication | publication_id → name, publication_date, type | 3НФ |
| Equipment | equipment_id → name, inventory_number, cost, purchase_date, laboratory_id | inventory_number → equipment_id (UK). **3НФ** |
| EquipmentRequest | request_id → request_date, status, justification, employee_id, equipment_id | 3НФ |
| EmployeeProject | (employee_id, project_id) → role, participation_start | Составной PK. **Нет частичных ФЗ:** employee_id ↛ role (роль зависит от обоих полей), project_id ↛ role. **Нет транзитивных.** **3НФ** |
| PublicationAuthor | (publication_id, employee_id) → author_order | Составной PK. **Нет частичных ФЗ.** **3НФ** |

### Доказательство 3НФ

1. **1НФ:** все атрибуты атомарны, нет повторяющихся групп.
2. **2НФ:** единственная таблица с составным ключом — EmployeeProject и PublicationAuthor. Все их неключевые атрибуты (role, participation_start, author_order) зависят от полного составного ключа, а не от его части. Частичные зависимости отсутствуют.
3. **3НФ:** все неключевые атрибуты зависят только от первичного ключа своей таблицы. Нет транзитивных зависимостей вида PK → non-key → non-key, так как связанные характеристики вынесены в отдельные таблицы (данные лаборатории — в Laboratory, оклад — в Position, данные гранта — в Grant).

Модель корректно нормализована и находится в 3НФ.

## 3. SQL: структура БД, индексы

```sql
CREATE TABLE Laboratory (
    laboratory_id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    location VARCHAR(100) NOT NULL,
    foundation_year INT CHECK (foundation_year > 1900)
);

CREATE TABLE Position (
    position_id SERIAL PRIMARY KEY,
    title VARCHAR(100) NOT NULL UNIQUE,
    salary NUMERIC(12,2) NOT NULL CHECK (salary > 0)
);

CREATE TABLE Employee (
    employee_id SERIAL PRIMARY KEY,
    last_name VARCHAR(50) NOT NULL,
    first_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    phone VARCHAR(30),
    birth_date DATE,
    hire_date DATE NOT NULL DEFAULT CURRENT_DATE,
    laboratory_id INT NOT NULL,
    position_id INT NOT NULL,
    FOREIGN KEY (laboratory_id) REFERENCES Laboratory(laboratory_id),
    FOREIGN KEY (position_id) REFERENCES Position(position_id)
);

CREATE TABLE Grant (
    grant_id SERIAL PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    amount NUMERIC(14,2) NOT NULL CHECK (amount > 0),
    source VARCHAR(150) NOT NULL,
    received_date DATE NOT NULL DEFAULT CURRENT_DATE
);

CREATE TABLE ScientificProject (
    project_id SERIAL PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    budget NUMERIC(14,2) NOT NULL CHECK (budget > 0),
    start_date DATE NOT NULL,
    end_date DATE,
    grant_id INT,
    FOREIGN KEY (grant_id) REFERENCES Grant(grant_id)
);

CREATE TABLE Publication (
    publication_id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    publication_date DATE NOT NULL,
    type VARCHAR(50) NOT NULL CHECK (type IN ('Article', 'Conference', 'Monograph', 'Thesis', 'Preprint'))
);

CREATE TABLE PublicationAuthor (
    publication_id INT NOT NULL,
    employee_id INT NOT NULL,
    author_order INT NOT NULL CHECK (author_order > 0),
    PRIMARY KEY (publication_id, employee_id),
    FOREIGN KEY (publication_id) REFERENCES Publication(publication_id),
    FOREIGN KEY (employee_id) REFERENCES Employee(employee_id)
);

CREATE TABLE Equipment (
    equipment_id SERIAL PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    inventory_number VARCHAR(50) NOT NULL UNIQUE,
    cost NUMERIC(12,2) CHECK (cost >= 0),
    purchase_date DATE DEFAULT CURRENT_DATE,
    laboratory_id INT NOT NULL,
    FOREIGN KEY (laboratory_id) REFERENCES Laboratory(laboratory_id)
);

CREATE TABLE EquipmentRequest (
    request_id SERIAL PRIMARY KEY,
    request_date DATE NOT NULL DEFAULT CURRENT_DATE,
    status VARCHAR(30) NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED', 'FULFILLED')),
    justification TEXT NOT NULL,
    employee_id INT NOT NULL,
    equipment_id INT NOT NULL,
    FOREIGN KEY (employee_id) REFERENCES Employee(employee_id),
    FOREIGN KEY (equipment_id) REFERENCES Equipment(equipment_id)
);

CREATE TABLE EmployeeProject (
    employee_id INT NOT NULL,
    project_id INT NOT NULL,
    role VARCHAR(100) NOT NULL,
    participation_start DATE NOT NULL DEFAULT CURRENT_DATE,
    PRIMARY KEY (employee_id, project_id),
    FOREIGN KEY (employee_id) REFERENCES Employee(employee_id),
    FOREIGN KEY (project_id) REFERENCES ScientificProject(project_id)
);
```

Индексы для ускорения JOIN по внешним ключам:

```sql
CREATE INDEX idx_employee_laboratory ON Employee(laboratory_id);
CREATE INDEX idx_employee_position ON Employee(position_id);
CREATE INDEX idx_project_grant ON ScientificProject(grant_id);
CREATE INDEX idx_request_employee ON EquipmentRequest(employee_id);
CREATE INDEX idx_request_equipment ON EquipmentRequest(equipment_id);
CREATE INDEX idx_pubauthor_employee ON PublicationAuthor(employee_id);
CREATE INDEX idx_equipment_lab ON Equipment(laboratory_id);
```

## 5. Триггеры

### Триггер бизнес-целостности
Сотрудник не может подать заявку на оборудование, если он не закреплён ни за одним научным проектом (нельзя выразить CHECK/FOREIGN KEY, т.к. проверка через другую таблицу — EmployeeProject).

```sql
CREATE OR REPLACE FUNCTION check_employee_project_before_request()
RETURNS TRIGGER AS $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM EmployeeProject ep
        WHERE ep.employee_id = NEW.employee_id
    ) THEN
        RAISE EXCEPTION 'Employee must participate in at least one project to request equipment';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_check_employee_project
BEFORE INSERT ON EquipmentRequest
FOR EACH ROW
EXECUTE FUNCTION check_employee_project_before_request();
```

### Триггер аудита/архивирования
Логирование всех операций (INSERT, UPDATE, DELETE) над заявками на оборудование.

```sql
CREATE TABLE EquipmentRequest_Audit (
    audit_id SERIAL PRIMARY KEY,
    request_id INT,
    old_status VARCHAR(30),
    new_status VARCHAR(30),
    old_data JSONB,
    new_data JSONB,
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    operation_type VARCHAR(10)
);

CREATE OR REPLACE FUNCTION audit_equipment_request()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        INSERT INTO EquipmentRequest_Audit (request_id, new_status, new_data, operation_type)
        VALUES (NEW.request_id, NEW.status, row_to_json(NEW)::jsonb, 'INSERT');
        RETURN NEW;
    ELSIF TG_OP = 'UPDATE' THEN
        INSERT INTO EquipmentRequest_Audit (request_id, old_status, new_status, old_data, new_data, operation_type)
        VALUES (NEW.request_id, OLD.status, NEW.status, row_to_json(OLD)::jsonb, row_to_json(NEW)::jsonb, 'UPDATE');
        RETURN NEW;
    ELSIF TG_OP = 'DELETE' THEN
        INSERT INTO EquipmentRequest_Audit (request_id, old_status, old_data, operation_type)
        VALUES (OLD.request_id, OLD.status, row_to_json(OLD)::jsonb, 'DELETE');
        RETURN OLD;
    END IF;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_audit_equipment_request
AFTER INSERT OR UPDATE OR DELETE ON EquipmentRequest
FOR EACH ROW
EXECUTE FUNCTION audit_equipment_request();
```

## 6. Сложный SQL-запрос

Вывести проекты, количество участников проекта, общий объём финансирования гранта и количество публикаций участников.

```sql
SELECT
    sp.name AS project_name,
    sp.budget,
    COUNT(DISTINCT ep.employee_id) AS participant_count,
    g.amount AS grant_amount,
    g.source AS grant_source,
    COUNT(DISTINCT pa.publication_id) AS publication_count
FROM ScientificProject sp
LEFT JOIN EmployeeProject ep ON ep.project_id = sp.project_id
LEFT JOIN Grant g ON g.grant_id = sp.grant_id
LEFT JOIN PublicationAuthor pa ON pa.employee_id = ep.employee_id
GROUP BY sp.project_id, sp.name, sp.budget, g.amount, g.source
HAVING COUNT(DISTINCT ep.employee_id) >= 1
ORDER BY participant_count DESC, sp.budget DESC;
```

Пояснение: запрос соединяет 5 таблиц (ScientificProject → EmployeeProject → PublicationAuthor → Employee → Grant через project_id), использует проекцию (SELECT), переименование столбцов (AS), групповые операции (COUNT(DISTINCT), GROUP BY) и сортировку (ORDER BY).

## 7. Код на C#

```csharp
using System;
using Npgsql;

class Program
{
    private const string ConnectionString =
        "Host=localhost;Username=postgres;Password=1234;Database=labs_db";

    static void Main()
    {
        using var conn = new NpgsqlConnection(ConnectionString);
        conn.Open();

        // 1. Создание таблиц
        ExecuteNonQuery(conn, @"
            CREATE TABLE IF NOT EXISTS Laboratory (
                laboratory_id SERIAL PRIMARY KEY,
                name VARCHAR(100) NOT NULL UNIQUE,
                location VARCHAR(100) NOT NULL,
                foundation_year INT CHECK (foundation_year > 1900)
            );
        ");

        // 2. Параметризованная вставка
        using var insertCmd = new NpgsqlCommand(@"
            INSERT INTO Laboratory (name, location, foundation_year)
            VALUES (@name, @location, @year)
            RETURNING laboratory_id", conn);

        insertCmd.Parameters.AddWithValue("name", "NewLab");
        insertCmd.Parameters.AddWithValue("location", "Building D");
        insertCmd.Parameters.AddWithValue("year", 2020);

        int newId = Convert.ToInt32(insertCmd.ExecuteScalar());
        Console.WriteLine($"Inserted laboratory with id = {newId}");

        // 3. Параметризованное обновление
        using var updateCmd = new NpgsqlCommand(@"
            UPDATE Laboratory
            SET name = @name, location = @location
            WHERE laboratory_id = @id", conn);

        updateCmd.Parameters.AddWithValue("name", "RenamedLab");
        updateCmd.Parameters.AddWithValue("location", "Building E");
        updateCmd.Parameters.AddWithValue("id", newId);
        updateCmd.ExecuteNonQuery();
        Console.WriteLine("Laboratory updated");

        // 4. Сложный запрос
        using var queryCmd = new NpgsqlCommand(@"
            SELECT
                sp.name AS project_name,
                COUNT(DISTINCT ep.employee_id) AS participant_count,
                COALESCE(g.amount, 0) AS grant_amount
            FROM ScientificProject sp
            LEFT JOIN EmployeeProject ep ON ep.project_id = sp.project_id
            LEFT JOIN Grant g ON g.grant_id = sp.grant_id
            GROUP BY sp.project_id, sp.name, g.amount
            ORDER BY participant_count DESC", conn);

        using var reader = queryCmd.ExecuteReader();

        Console.WriteLine("\n--- Project Report ---");
        Console.WriteLine($"{"Project",-30} {"Participants",-15} {"Grant"}\n");

        while (reader.Read())
        {
            string project = reader["project_name"].ToString();
            int participants = Convert.ToInt32(reader["participant_count"]);
            decimal grant = Convert.ToDecimal(reader["grant_amount"]);

            Console.WriteLine($"{project,-30} {participants,-15} {grant,10:F2}");
        }

        conn.Close();
    }

    static void ExecuteNonQuery(NpgsqlConnection conn, string sql)
    {
        using var cmd = new NpgsqlCommand(sql, conn);
        cmd.ExecuteNonQuery();
    }
}
```
